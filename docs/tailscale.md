# Tailscale identity on hub-11

hub-11 is node `hub-11` (100.88.4.63) on the tailnet. Its identity is one file:

```
/var/lib/tailscale/tailscaled.state      (root, 0600, ~2.8 KB)
```

That file is the node's private key. Whoever has it *is* hub-11 on the tailnet.

## Where copies live

| location | purpose |
|---|---|
| hub-11 `/var/lib/tailscale/tailscaled.state` | live |
| lab `~/hub11-backups/tailscaled.state` (0600, dir 0700) | the single backup |

It is **not** in the repo, **not** in the rootfs tarball (`scripts/build-rootfs.sh`
fails its leak gate if it ever is), and the old ad-hoc tarball that carried it
was deleted on 2026-09-06.

## After a reflash of p6

The fresh rootfs has `tailscale` installed and `tailscaled` enabled but no state.
Restore the identity before the first `tailscale up`:

```
scp ~/hub11-backups/tailscaled.state hub-11:/tmp/
ssh hub-11 'sudo systemctl stop tailscaled && sudo install -m 600 -o root -g root /tmp/tailscaled.state /var/lib/tailscale/ && rm /tmp/tailscaled.state && sudo systemctl start tailscaled && tailscale status --self --peers=false'
```

Expected: `100.88.4.63 hub-11 ...` with the same node ID as before. Key expiry
is 2027-02-14; `tailscale up --operator=nyx` re-auths when it lapses.

If the SSH host keys were regenerated by the new rootfs (they always are), drop
the stale known_hosts entries on lab first:

```
ssh-keygen -R hub-11; ssh-keygen -R 100.88.4.63; ssh-keygen -R 192.168.0.8
```

## Fresh identity instead (new node)

Skip the restore and run `sudo tailscale up --operator=nyx`; the box appears as
a new node and the old `hub-11` entry must be removed in the admin console.

## Rotating the key

`sudo tailscale logout && sudo tailscale up --operator=nyx`, then replace the
backup: `ssh hub-11 'sudo cat /var/lib/tailscale/tailscaled.state' > ~/hub11-backups/tailscaled.state`.
